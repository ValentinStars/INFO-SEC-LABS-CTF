# Task 01: IITU 10000 (Поиск иглы в стоге сжатых данных)

> **Категория**: Forensic / Stego / Data Analysis  
> **Сложность**: Easy-Medium  
> **Ключевой файл**: `iitu_10000.zip` (38 МБ)

---

## В чем суть задачи

В архиве лежит 10 000 папок, в каждой ровно по одной картинке 100x100 в градациях серого. Имена файлов — 12-значные хэши (например, `e249287d9fab.png`), и все файлы на диске имеют совершенно одинаковый размер — ровно **3853 байта**.

Задача: найти среди этой массы единственное изображение с логотипом/надписью **IITU**, забрать имя этого файла в первую часть флага, а номер папки возвести в куб, чтобы получить пароль ко второму заданию.

Формат флага этапа:
```text
Flag_{filename.png_}
```

## Как это решается: ход мыслей и грабли

### Грабли №1: Распаковать всё на диск и смотреть глазками
Если распаковать 10 тысяч файлов в одну директорию, проводник или файловый менеджер зависнет на генерации превью. Глазами отсмотреть 10 000 картинок с шумом — верный способ испортить зрение.

### Грабли №2: Grep по строкам
Первая мысль новичка — грепнуть строку `IITU` или `iitu` прямо по бинарникам. Но внутри PNG пиксельные данные упакованы в zlib-стрим (блок `IDAT`), поэтому открытым текстом слово в байтах не лежит.

### Грабли №3: Гистограммы пикселей
Если посчитать распределение яркости пикселей у картинок, оказывается, что автор таски специально подготовил одинаковый состав пикселей: у каждой картинки ровно 7062 белых пикселей (яркость 255) и ровно по ~490 пикселей каждого значения от 243 до 248. То есть все картинки — это одна и та же палитра, перемешанная в разных порядках.

### Рабочий инженерный подход: Энтропия и zlib
Как устроен формат PNG:
1. Пиксельные данные перед записью в файл сжимаются алгоритмом Deflate (zlib).
2. Белый шум (случайная перестановка пикселей) сжимается **очень плохо** — размер сжатого блока `IDAT` остаётся большим (~3500–3760 байт).
3. Картинка со связным текстом или логотипом имеет **структуру**: соседние пиксели одинаковые, линии сплошные, фон непрерывный. Такой поток сжимается алгоритмом LZ77/Хаффмана **в разы эффективнее**.
4. Чтобы все файлы на диске казались одинаковыми (3853 байта), автор добавил кастомный чанк-заполнитель `npAD`. Но сам размер исходного `IDAT` внутри PNG-структуры он скрыть не смог!

Достаточно за пару секунд пробежаться по архиву прямо в оперативной памяти (без распаковки на диск) и найти файл с **минимальным размером чанка `IDAT`**.

## Автоматический запуск решения

В этой папке лежит готовый скрипт [`solve.py`](file:///home/valentin_stars/INFO-SEC-LABS-CTF/tasks/01-iitu-10000/solve.py):

```bash
python3 solve.py
```

Что делает скрипт:
1. Открывает `iitu_10000.zip` через `zipfile`.
2. Читает заголовки чанков каждого PNG без сохранения на диск.
3. Находит рекордсмена по сжатию: `6741/1c3aa737eac3.png` — размер его `IDAT` составляет всего **2954 байта** (у всех остальных — больше 3300-3700).
4. Отрисовывает найденную картинку прямо в консоль символами Unicode (отчетливо видны буквы **IITU**).
5. Считает куб номера папки: $6741^3$.
